# Система расчёта прибыли мебельного салона

Учебное клиент-серверное приложение на Java для учёта продаж, расходов и расчёта прибыли мебельного салона. Разработано в рамках курсового проекта по дисциплине «Программирование сетевых приложений».

## Возможности

- Учёт товаров, категорий и складских остатков.
- Ведение клиентской базы и просмотр истории покупок.
- Оформление продаж, применение скидок и изменение статуса заказа.
- Учёт операционных расходов и комиссий менеджеров.
- Расчёт выручки, себестоимости, валовой, операционной и чистой прибыли за период.
- Формирование отчётов о прибылях и убытках, маржинальности товаров, комиссиях и динамике продаж.
- Экспорт отчётов в CSV.
- Управление пользователями, разграничение прав и журнал действий.

В системе предусмотрены три роли:

| Роль | Основные задачи |
| --- | --- |
| Администратор | Управление пользователями, товарами, категориями и скидками, просмотр журнала действий |
| Менеджер по продажам | Работа с клиентами и продажами |
| Бухгалтер | Учёт расходов, расчёт прибыли, просмотр комиссий и финансовых отчётов |

## Технологии и устройство

Java 25, JavaFX 25.0.2, Maven, MySQL, JDBC, HikariCP, BCrypt, SLF4J и JUnit 5.

Проект состоит из трёх Maven-модулей:

| Модуль | Назначение |
| --- | --- |
| `client` | Интерфейс на JavaFX: FXML, CSS и контроллеры экранов |
| `server` | Обработка запросов, бизнес-логика, расчёты и доступ к БД через DAO |
| `common` | Общие модели, DTO, запросы, ответы, перечисления и конфигурация |

Клиент обменивается с сервером сериализованными Java-объектами по TCP. Сервер обрабатывает подключения в пуле потоков и работает с MySQL через пул соединений HikariCP. Пароли пользователей хранятся в виде BCrypt-хешей. Для денежных расчётов используется `BigDecimal`.

Чистая прибыль рассчитывается по завершённым продажам за выбранный период:

```text
Чистая прибыль = Выручка − Себестоимость − Операционные расходы − Комиссии
```

## Подготовка к запуску

Потребуются **JDK 25**, **Maven** и **MySQL**. Текущая конфигурация JavaFX в `pom.xml` рассчитана на Windows (`javafx.platform=win`).

### База данных и настройки

В корне проекта находится `Скрипт базы данных.sql`. Он создаёт базу `furniture_sales_db`, 12 таблиц, включая журнал действий `audit_log`, а также начальные роли, категории товаров и расходов.

**При выполнении скрипт удаляет существующие таблицы проекта вместе с данными и создаёт их заново.** Используйте его для первоначальной настройки или сброса учебной базы.

Для импорта откройте консоль MySQL из папки проекта:

```powershell
mysql -u root -p --default-character-set=utf8mb4
```

Введите пароль MySQL, затем в его консоли выполните:

```sql
SOURCE Скрипт базы данных.sql;
exit;
```

В `common/src/main/resources/config.properties` настройте подключение:

```properties
server.host=localhost
server.port=8081
server.thread.pool.size=10

db.url=jdbc:mysql://localhost:3306/furniture_sales_db?useSSL=false&serverTimezone=Europe/Minsk&allowPublicKeyRetrieval=true
db.user=furniture_user
db.pass=CHANGE_ME
db.pool.size=10
```

Укажите свои реквизиты MySQL. Для подключения с другого компьютера измените `server.host` на адрес сервера.

### Сборка

```powershell
mvn clean package -DskipTests
```

Maven соберёт модули и создаст JAR-файлы с зависимостями. Тесты в этой команде пропущены, поскольку часть из них требует подготовленной базы данных.

### Запуск

Сначала запустите сервер:

```powershell
java -jar server/target/server-1.0-SNAPSHOT-server.jar
```

В другом терминале из корня проекта запустите клиент:

```powershell
java -jar client/target/client-1.0-SNAPSHOT-client.jar
```

Если схема БД подготовлена и в таблице пользователей нет записей, сервер создаёт учётную запись `admin` с паролем `admin123`. После первого входа замените пароль через управление пользователями. Этот механизм создаёт начального пользователя и роли, но не схему БД.

## Тестирование

В `common/src/test` и `server/src/test` находятся модульные и интеграционные тесты проверки ролей, хеширования паролей, валидации операций, сервисов и обработки запросов.

```powershell
mvn test
```

Интеграционные тесты подключаются к MySQL через ту же конфигурацию и создают и удаляют записи. Для их запуска используйте отдельную тестовую базу с подготовленной схемой.
